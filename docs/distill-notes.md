# 自博弈蒸馏工具 `tools-distill.js` · 使用说明

> 用途：批量 NPC vs NPC 自对弈，搜索 `DEFAULT_WEIGHTS`（defenseW/selfW/keepW/playW）的最优值，写回内核出厂设置。

## 用法

```bash
cd C:/Users/Gary/WorkBuddy/2026-09-19-08-30-00/happy14

# 快速粗扫（N=150/轮，约1-2分钟）
node tools-distill.js --quick

# 完整蒸馏（N=300/轮，约3-5分钟）
node tools-distill.js

# 跑完觉得对，直接写回 game-core.js（会打印三端同步收尾提醒）
node tools-distill.js --write
```

## 核心机制

1. **坐标下降**：逐个尝试 `[0.6×, 0.8×, ×1.0, 1.25×, 1.6×]` 每个权重，胜率提升≥`MIN_GAIN`(默认 0.8 pp) 就采纳。
2. **配对发牌 + 先后手交替**（复用 `difficulty-lab.js` 纪律）：同种子 = 同一副牌，消除噪声。
3. **双校验**：建议值跑完会对比 **hard 和 hell 两个难度各 1000 局**（seed=900000 固定），确保：
   - 不破坏单调性：`hell ≥ hard ≥ medium ≥ easy`
   - 至少一个难度胜率有实质改善（≥1 pp）

## 2026-10-07 全量蒸馏（N=300）结果：收敛，不写盘

- 基线 hard 胜率 70.7%；坐标下降两轮，唯一采纳候选 `defenseW 2→1.2`，但 1000 局配对验证：hard 70.7%→70.5%（-0.2pp）、hell 92.2%→91.2%（-1.0pp）——"改进"实为变差，拒绝写盘。
- 粗扫（N=150）曾建议 defenseW=2.5，全量（N=300）建议 1.2：方向相反的噪声互相印证 4 权重空间已收敛在局部最优。
- **结论：纯调 4 权重榨不出下一截了。** 下一个台阶在结构层：`rankMoves` 的 top-K 剪枝（`dominanceGroups().slice(0,4)`）、rollout 抽样数/深度、罚牌 rank 曲线——把这几项进搜索空间才谈得上持续提强度。

## 踩坑（2026-10-07 实测）

- **样本量陷阱**：`--quick` 时 N_SCAN=150，单轮候选胜率波动可达 ±2-3 pp，校准台会给出**看似最优实则有害**的权重（如 defenseW 2→2.5 让 hard 从 72% 跌到 69.8%）。
- **铁律**：任何权重改动**必须**在 `N_VERIFY ≥ 1000` 下通过单调性检查才能落地。跑完整蒸馏（`node tools-distill.js`，N_SCAN=300）比快速模式可靠得多。
- **验证失败不写盘**：工具本身不会 `--write`，只有用户显式加 `--write` 才改内核。
